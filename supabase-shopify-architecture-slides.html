Debugging & Resilience

Where Bugs Will Happen (And How We Prevent Them)

Critical edge cases in production and the proven defense mechanisms implemented in our codebase.

⚠️ Edge Case: Overselling on High-Demand Drop Launches

Concurrency Risk

Scenario: 50 users simultaneously hit "Buy" for the last 3 units of "Spirit Gives Life Tee (Size L)".
The Fix: The frontend never decides stock availability. Shopify holds an atomic Inventory Lock at the checkout boundary. If stock reaches 0, Shopify automatically prevents payment completion.

Shopify API response: { error: "INVENTORY_OUT_OF_STOCK", variantId: "gid://shopify/ProductVariant/..." } → Frontend triggers real-time "Sold Out" toast.

⚠️ Edge Case: Auth State Race Condition (Session Desync)

Auth Lifecycle

Scenario: User leaves tab open overnight. JWT token expires, causing profile or review fetch to fail.
The Fix: Supabase client handles seamless background token rotation (autoRefreshToken: true). React subscribes to supabase.auth.onAuthStateChange() to seamlessly update user state without logging them out.

Event: 'TOKEN_REFRESHED' → Updates cached JWT in memory without page reload.

⚠️ Edge Case: Giant 25MB iPhone 4K Photo Uploads

Storage & Performance

Scenario: Customer uploads an uncompressed 25MB HEIC/JPEG outfit photo, blowing up storage bandwidth.
The Fix: Client-side HTML5 Canvas compression before upload. Compress images to WebP / max 1600px width (under 400KB) before transmitting to Supabase Storage.

Compression pipeline: 24.8 MB raw HEIC → 320 KB optimized WebP image (98.7% bandwidth savings).

⚠️ Edge Case: Hostinger Production Domain CORS Blocks

Network Configuration

Scenario: Custom domain https://spiritbeing.in gets blocked by Supabase Auth redirects or API calls.
The Fix: Explicitly add https://spiritbeing.in and wildcard https://*.spiritbeing.in to the Supabase Allowed Callback URLs & Web Origins list.

Configured in: Supabase Dashboard → Authentication → URL Configuration → Redirect URLs.
Risk & Compliance

What Risks Do We Deal With? (And How We Win)

A breakdown of payment liability, database protection, and credential hygiene.

PAYMENT SECURITY 🔒

Zero PCI-DSS Liability

Because customers enter credit card numbers, UPI IDs, and CVVs on Shopify's Shop Pay domain, our storefront never touches or stores raw card data. 100% compliant by design.

DATABASE DEFENSE 🛡️

Postgres Row-Level Security

Even if an attacker intercepts our public API keys, PostgreSQL verifies auth.uid() = user_id. Nobody can view or edit someone else's addresses or order records.

KEY HYGIENE 🔑

Public vs Secret Keys

VITE_SUPABASE_ANON_KEY is safe for the browser. The Supabase service_role master key is NEVER included in frontend code to prevent full database bypass.

Supply Chain

How Inventory Connects & Stays Accurate

Real-time multi-channel inventory control ensuring zero overselling across limited drop releases.

1. Single Source of Truth

Shopify is the authoritative inventory master. When warehouse staff scan items in or adjust stock:

  • 📦 Warehouse Adjustments: Instantly reflected in Storefront API.
  • 🔄 Real-time Variant Polling: When a user picks 'Size M', app queries live availability.
  • 🚫 Automated Sold Out Switch: UI disables "Add to Bag" and switches to "Notify Me" automatically.

2. Drop Launch Protection

During high-traffic drops (e.g. 500 visitors competing for 50 pieces):

  • ⚡ Cart Reservation: Shopify reserves inventory for active checkout sessions for 10 minutes.
  • ⏱️ Cart Abandonment Release: If payment isn't finished in 10 min, stock unlocks for the next waiting customer.
  • 🛡️ Zero Stale Reads: Checkout step executes direct inventory reservation check.

1-Click Google Sign-In

// Order receipt created { order_id: "#SB-10492", customer_email: "rahul@gmail.com" }

When user posts an outfit photo review, Supabase cross-checks their email and auto-awards the green badge.

-- SQL cross-check SELECT EXISTS ( SELECT 1 FROM orders WHERE email = user_email );
